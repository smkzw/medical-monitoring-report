# 经验沉淀（来自医学监察实践与上游三技能）

1. **先问口径再建**：人群、USV、基线、分级标准版本、非分级表指标阈值、盲态是最常返工的项。
2. 受试者在所有列表中**按数字排序**；纵向数据按**实际评估日期**排序（含计划外）。
3. 单侧或定性参考范围合并为单一显示值（`≤40`），不要强行拆成上下限两列。
4. 必须看渲染结果，不只看 JSON：UI 截断会被误认为数据缺失。
5. 判 CS 未关联时，若同期有疑似 AE，问“是否关联”而不是“是否补报 AE”，避免重复 AE。
6. NCS 但达分级 ≥2 级：先质疑判定口径（NCS-before-CS），再看是否漏报。
7. 仅关联 MH：比较给药后与规定基线的等级/数值，加重才发 query。
8. 同中心同指标数值几乎相同却一个 CS 一个 NCS：提示中心判定尺度，而非以多数为准。
9. 规定基线缺失要显式标注“替代基线”，不能悄悄换基线。
10. CRO 已发质疑：先查重再发；同一 EDC 单元格只发一条（合并事实）。
11. 下游风险模块（如 query 生成）须再次确认人群并以源 listing 为最终依据；不要从图表或截断列表推断风险。
12. 方案正文与 SoA 脚注冲突很常见（如基线时间点），用 consensus 显式裁定并标来源。
13. 中心层面偏离只用于中心沟通，不对个例发 query。
14. 时间线中 CM/MH 很早开始的条带截断到 ICF 前 `preDays` 天，否则主体区间被压缩。
15. 单位以 `10^` 开头需写成 `×10^9/L`；数值与单位之间留空格。
16. ECharts 需 v6（轴断裂）；离线交付必须把 echarts.min.js 打包进 `HTML/assets/`（build_site.py 已处理）。
17. 未识别的模块（PK 只有采样状态、无 IB、无 PD）在方法学页明确声明，而不是静默省略。
18. **去过拟合审计（2026）**：首版把 CTCAE v6.0 阈值写死在 ctcae.py/ctcae.js、页面文案写死“CTCAE 6.0”、基线只支持“访视+时间点”、AESI 只支持术语正则。
    已改为：版本化分级表（v5.0/v6.0/自定义 + overrides，未指定版本即报错）、指标自动映射与单位换算、基线规则引擎（访视/首剂前最近/均值/逐指标）、
    AESI 定义（术语/PT/SOC/minGrade/组合规则）、AE 收集期/TEAE、报告时限、访视窗锚点。新增任何规则先问“这是方案写的还是上个项目写的？”
19. 检查模块（妇科超声、眼科、影像等）不写死：listing 有才出现，统一走通用「专项检查」组；页面文案不得出现当前研究不存在的模块。
20. 日期差 `days(a, b) = a − b`：写“距锚点天数/报告延迟”时用 `days(后, 前)`，并用测试数据验证正负号。
